# Idea Validation Roadmap Builder

Source: *The 10x Method* (Hexa), Chapter II — "Finding and Validating the Idea", pages 40-45.

## What this skill does

Produces a concrete, time-boxed validation roadmap for a founder's idea, following Hexa's own 3-step validation process, and flags idea-killers early using real examples from Hexa's own portfolio (including ideas that didn't pass validation).

## The 3-step validation process (from the book)

**1. Become an expert**
Before building anything, the founder must deeply understand the problem space:
- Talk to as many potential users as possible (not just friends/network — real target users).
- Read everything available on the space: competitor products, industry reports, forums, review sites.
- Identify the 2-3 sharpest, most specific pain points people describe unprompted.

**2. Scope the idea**
- Narrow from "a broad space" to a specific wedge: one user type, one use case, one clear value proposition.
- Write a one-sentence description of what the product does and for whom — if it takes a paragraph, it's not scoped enough yet.
- Identify what's explicitly *out* of scope for v1.

**3. Create wireframes**
- Build low-fidelity wireframes (the book recommends Hexa's own Figma plugin, Blocks.pm, for this) — deliberately rough, not polished.
- Use these wireframes in conversations with prospective users to react to something concrete rather than a verbal pitch.
- Wireframes should provoke reactions ("I'd never use this because..." / "this is missing X") — that reaction is the signal you're looking for.

## The validation timeline

The book frames validation as a bounded phase, not an open-ended exploration — founders should set a deadline (typically a few weeks) to reach a go/no-go decision, not drift indefinitely in "research mode."

## Workflow

1. **Get the idea and its category** if available (pair this with the `idea-categorizer` skill's output — the validation approach differs by category: Category 3 "category creation" ideas are much harder to validate through direct customer discovery since users can't articulate a need they've never conceived of; expect to rely more on behavioral observation and smaller, riskier bets).
2. **Build the roadmap in 3 phases**, each with:
   - Concrete actions (number of user interviews to run, specific questions to ask, competitor research to complete)
   - A realistic time-box (days/weeks)
   - A clear "done" criterion before moving to the next phase
3. **Add a go/no-go checkpoint** at the end, explicitly modeled on Hexa's own practice of killing ideas that don't pass validation — ask the founder to define in advance what would make them walk away (this is the hardest and most valuable part; founders are biased toward their own idea).
4. **Flag idea-killers early**: if in step 1 (become an expert) the founder can't find anyone who cares, or in step 3 (wireframes) reactions are lukewarm rather than sharp, that's a signal to pause before building — say so directly rather than softening it.

## Output format

Present as a simple 3-phase table:

| Phase | Actions | Time-box | Done when... |
|---|---|---|---|
| 1. Become an expert | ... | ... | ... |
| 2. Scope the idea | ... | ... | ... |
| 3. Create wireframes | ... | ... | ... |

Followed by:
- **Go/no-go checkpoint**: what would make this idea a "no"
- **Category-specific caution** (if paired with idea-categorizer output)

Keep it actionable — this should read like a to-do list a founder can start executing today, not a strategy essay.
